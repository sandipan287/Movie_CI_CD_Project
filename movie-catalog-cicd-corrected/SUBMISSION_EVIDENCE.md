# Submission Evidence Checklist

The reviewer feedback requires more than workflow YAML files. Before resubmitting, provide a public GitHub repository link and evidence that all four workflows actually run successfully.

## 1. Public GitHub repository

Submit the URL of the **public GitHub repository** containing this complete project.

Example format (replace with your real URL):
`https://github.com/<your-username>/<your-repository>`

Do not submit a placeholder as the final evidence.

## 2. Four successful GitHub Actions workflows

The repository must show successful runs for all four workflows:

1. `Frontend Continuous Integration`
2. `Backend Continuous Integration`
3. `Frontend Continuous Deployment`
4. `Backend Continuous Deployment`

Recommended evidence: take one GitHub Actions screenshot where all four latest workflow runs are visible and show a green/success status, plus individual run screenshots if the submission form requires them.

## 3. Frontend application URL

After deployment, run:

```bash
kubectl get svc movie-frontend
```

Open the EXTERNAL-IP/hostname for `movie-frontend` in a browser and verify that the Movie Catalog loads. Submit that working URL, or a screenshot if the platform accepts screenshots instead.

## 4. Backend API URL

Run:

```bash
kubectl get svc movie-backend
```

Open:

`http://<backend-load-balancer>:5000/api/health`

It should return JSON similar to:

```json
{"status":"ok"}
```

Also verify:

`http://<backend-load-balancer>:5000/api/movies`

Then submit the working backend URL, or the equivalent screenshot.

## 5. Kubernetes evidence requested by the reviewer

Capture:

```bash
kubectl get all
```

and:

```bash
kubectl describe deployment movie-frontend
kubectl describe deployment movie-backend
```

If the output is long, take multiple screenshots.

## 6. ECR image evidence

In both ECR repositories, open the latest image and capture its image/tag details:

- frontend ECR repository — latest successful image
- backend ECR repository — latest successful image

The tag generated by these workflows is the GitHub commit SHA.

## Final pre-submission check

- [ ] Public GitHub repository URL submitted
- [ ] Frontend CI has a successful run
- [ ] Backend CI has a successful run
- [ ] Frontend CD has a successful run
- [ ] Backend CD has a successful run
- [ ] Frontend LoadBalancer URL works in a browser
- [ ] Backend `/api/health` URL works
- [ ] Backend `/api/movies` URL works
- [ ] `kubectl get all` evidence captured
- [ ] `kubectl describe deployment movie-frontend` evidence captured
- [ ] `kubectl describe deployment movie-backend` evidence captured
- [ ] Latest frontend ECR image details captured
- [ ] Latest backend ECR image details captured
- [ ] No AWS credentials committed to GitHub
